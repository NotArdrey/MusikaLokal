# MusikaLokal Non-Technical System Flow Defense Script

## Opening

Good day, respected panelists. I will now explain the system flow of **MusikaLokal** in a simple and non-technical way.

MusikaLokal is a platform designed for the local music community. It helps musicians, studio owners, venue owners, producers, fans, and administrators connect with each other in one system. The main purpose of the system is to make it easier to discover music opportunities, book studios, manage gigs, communicate with other users, and monitor activities inside the platform.

For this explanation, I will focus on the basic flow of the system, starting from login and registration, then I will explain an example where a musician books a studio.

## 1. Opening the Application

The flow starts when the user opens the MusikaLokal application.

The first thing the user sees is the welcome or login page. From here, the user can either log in if they already have an account, register if they are a new user, recover their password, or explore limited features as a guest.

This is the entry point of the system.

## 2. Login Flow

If the user already has an account, they will choose the login option.

The user enters their email and password. After that, the system checks the account details.

If the entered details are incorrect, the system shows a message telling the user that the login failed.

If the details are correct, the system allows the user to enter the application.

After logging in, the system identifies what type of user they are. For example, the user may be a musician, studio owner, venue owner, producer, fan, or administrator.

Once the system knows the user's role, it brings the user to the proper page for their account.

## 3. Registration Flow

If the user does not have an account, they can choose the register option.

During registration, the user provides basic information such as name, email, password, and user type.

For example, if the user wants to use the platform as a musician, they select musician as their role.

After completing the registration form, the system creates the account. Once the account is ready, the user can log in and start using the features available for their role.

This registration process is important because the system needs to know what kind of user is entering the platform.

## 4. Role-Based Flow

After login or registration, the system shows features based on the user's role.

For musicians, the system provides access to browsing studios, searching for gigs, managing bookings, joining groups, using chat, viewing notifications, and exploring music-related content.

For studio owners, the system provides access to adding and managing studio listings, receiving booking requests, communicating with musicians, and viewing booking activities.

For venue owners, the system provides access to posting gigs, managing applications, and coordinating with musicians or producers.

For producers, the system allows them to manage production teams and related activities.

For fans, the system focuses more on discovering music content and viewing the social feed.

For administrators, the system provides management and monitoring features through the admin side of the platform.

## 5. Example Flow: Musician Books a Studio

Now I will explain one sample flow: a musician booking a studio.

First, the musician logs in to the MusikaLokal application.

After logging in, the musician goes to the home or discovery section. In this section, the musician can browse available studios.

The musician can search for a studio based on their needs, such as location, available services, equipment, price, or schedule.

Once the musician finds a studio they are interested in, they tap or open the studio listing.

The system then shows the studio details. This may include the studio name, photos, location, description, available equipment, price, and other important information.

If the musician decides to book the studio, they choose the available date and time or session.

After selecting the schedule, the musician submits the booking request.

The system then checks the booking request. If the selected schedule is no longer available or if some information is missing, the system informs the musician.

If the booking request is valid, the system records the request and shows it in the musician's booking page.

At this point, the booking is now waiting for action from the studio owner.

## 6. Studio Owner Flow

On the studio owner's side, the studio owner logs in to their account.

The studio owner goes to their booking or management page and sees the new booking request from the musician.

The studio owner reviews the request, including the musician's information, selected schedule, and other booking details.

After reviewing, the studio owner can accept, decline, or manage the booking request.

If the studio owner accepts the booking, the musician will see that the booking has been approved.

If the studio owner declines the booking, the musician will also be informed.

This allows both users to track the status of the booking clearly.

## 7. Notification Flow

Notifications help users stay updated.

For example, when a musician sends a booking request, the studio owner can receive a notification.

When the studio owner accepts or declines the request, the musician can also receive a notification.

This makes the process easier because users do not need to constantly check manually. The system helps inform them when there is an update.

## 8. Chat Flow

After the booking request is made, the musician and studio owner may need to discuss details.

For example, the musician may ask about available instruments, recording equipment, parking, arrival time, or studio rules.

The chat feature allows the musician and studio owner to communicate directly inside the platform.

This helps avoid confusion and keeps the conversation related to the booking in one place.

## 9. Payment or Wallet Flow

If payment is required, the musician can proceed to the payment or wallet process.

The system records the payment-related activity so that both sides can track the booking properly.

This helps make the transaction more organized and connected to the booking record.

## 10. Completion Flow

After the scheduled studio session is completed, the booking can be marked as completed.

The musician and studio owner may also proceed to review or feedback.

This helps future users know more about the quality of the studio or the reliability of the musician.

The completed booking remains in the user's activity history.

## 11. Admin Monitoring Flow

The administrator does not join the booking process like a musician or studio owner.

Instead, the administrator monitors the platform.

The admin can review users, reports, identity verification, content, and other activities that need supervision.

If there is a problem, such as a reported account or inappropriate activity, the admin can take the necessary action.

This helps keep the platform safe and organized.

## Simple Flow Summary

The system flow can be summarized like this:

1. The user opens the MusikaLokal app.
2. The user logs in or registers.
3. The system identifies the user's role.
4. The user is directed to the features for that role.
5. A musician searches for a studio.
6. The musician views studio details.
7. The musician selects a date and time.
8. The musician sends a booking request.
9. The studio owner receives the request.
10. The studio owner accepts, declines, or manages the booking.
11. The musician receives an update.
12. The users may communicate through chat.
13. Payment and completion may follow.
14. The admin monitors the platform when needed.

## Closing

To conclude, the MusikaLokal system flow starts with login or registration. After that, the system identifies the user's role and shows the correct features. In the example of a musician booking a studio, the musician searches for a studio, views the details, sends a booking request, and waits for the studio owner's response. Notifications and chat help both users communicate and stay updated.

This flow shows how MusikaLokal helps local music users connect, book services, and manage activities in a more organized and convenient way.

Thank you.
